3. ARCHITECTURE
=============================================================================

Before (Legacy Layout):
-----------------------
Memory: Separate K and V arrays
  K: [token][head][dim]
  V: [token][head][dim]
  
Access Pattern:
  For each token:
    Load K (cache miss)
    Compute attention
    Load V (cache miss)  <- Different array, another miss
    
Cache Efficiency: LOW
  - K and V in different cache lines
  - Strided access across tokens
  - No prefetch opportunities

After (Optimized Layout):
-------------------------
Memory: Unified [token][head][K/V][dim]
  Token 0: [Head 0: K(128) + V(128)] [Head 1: K(128) + V(128)] ...
  Token 1: [Head 0: K(128) + V(128)] [Head 1: K(128) + V(128)] ...
  
Access Pattern:
  For each token:
    Load K+V (single cache line hit)
    Compute attention
    Prefetch next token (4-8 ahead)
    
Cache Efficiency: HIGH
  - K and V contiguous (same cache line)
  - Sequential token access
  - Hardware prefetch friendly

Performance Gain: 2x
