# RawrXD Evidence Generation Pipeline

## Overview

The RawrXD build system automatically generates verifiable evidence artifacts on every **Release** build. This transforms sovereignty claims from architectural intent into independently auditable facts.

## Pipeline Flow

```
Release Build
     │
     ├─→ Compile (C++20 + MASM64)
     │
     ├─→ Link (RawrXD-Win32IDE.exe)
     │
     ├─→ Generate Evidence (7 artifacts)
     │      │
     │      ├─→ binary_hash.txt
     │      ├─→ compiled_sources.txt
     │      ├─→ linked_libraries.txt
     │      ├─→ binary_imports.txt
     │      ├─→ architecture_report.json
     │      ├─→ dependency_manifest.json
     │      └─→ benchmark_metadata.json
     │
     └─→ Verification Gates (PASS/FAIL)
```

## Evidence Artifacts

All artifacts are generated in `build/evidence/` after each Release build.

**Purpose**: SHA256 hash for reproducibility verification

**Verification**:

## Verification Gates

After each build, the following automated gates run:

### Gate 1: Binary Hash Verification
- **Check**: SHA256 hash matches stored value
- **Purpose**: Ensure binary hasn't been modified post-build
- **Failure Mode**: Binary tampered, wrong binary tested

### Gate 2: Source Inventory Analysis
- **Check**: No integration pattern filenames (`_bridge`, `_adapter`, `_wrapper`)
- **Purpose**: Enforce sovereign naming conventions
- **Failure Mode**: Integration patterns reintroduced

### Gate 3: Dependency Manifest Compliance
- **Check**: `compliance_status == "PASS"`
- **Purpose**: Verify no prohibited dependencies
- **Failure Mode**: llama.cpp, ggml, or other frameworks linked

### Gate 4: Binary Import Table Inspection
- **Check**: No prohibited DLLs in import table
- **Purpose**: Verify no runtime dependencies on external frameworks
- **Failure Mode**: External inference DLLs detected

### Gate 5: Architecture Report Validation
- **Check**: SHA256 present, size within bounds
- **Purpose**: Ensure report completeness
- **Failure Mode**: Report generation failed

### Gate 6: Benchmark Metadata Completeness
- **Check**: Hardware, software, model info populated
- **Purpose**: Ensure benchmark reproducibility
- **Failure Mode**: Metadata not updated

### Gate 7: Linked Libraries Analysis
- **Check**: No prohibited libraries in linker memory
- **Purpose**: Verify build-time sovereignty
- **Failure Mode**: Prohibited libraries linked

## Troubleshooting

### Evidence Directory Missing
**Problem**: `build/evidence/` not created  
**Solution**: Ensure you're building in **Release** configuration (evidence only generated for Release builds)

### Verification Gate Failed
**Problem**: One or more gates report FAIL  
**Solution**: Review the specific error message:
- **Dependency scan failed**: Check for prohibited libraries in CMakeLists.txt
- **Import table failed**: Ensure no external DLLs linked
- **Hash mismatch**: Binary may have been modified post-build

### Benchmark Metadata Shows "PENDING"
**Problem**: `benchmark_metadata.json` has PENDING values  
**Solution**: Run the benchmark executable to populate results:
```powershell
.\build\bin\RawrXD-Win32IDE.exe --benchmark
```

## Security Considerations

### Hash Verification
Always verify the SHA256 hash before running benchmarks or distributing binaries:

```powershell
# Verify before testing
$storedHash = Get-Content build\evidence\binary_hash.txt
$computedHash = (Get-FileHash build\bin\RawrXD-Win32IDE.exe -Algorithm SHA256).Hash
if ($storedHash -eq $computedHash) {
    Write-Host "✓ Binary verified" -ForegroundColor Green
} else {
    Write-Host "✗ Binary mismatch - DO NOT RUN" -ForegroundColor Red
}
```

### Import Table Audit
Regularly audit the import table for unexpected DLLs:

```powershell
# List all DLL imports
dumpbin /IMPORTS build\bin\RawrXD-Win32IDE.exe | Select-String '\.dll'
```
