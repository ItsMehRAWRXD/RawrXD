# AGGREGATE_DECODE_DEEP2_NATIVE_RUNTIME_001 — S07 CPU PARITY (first-token PASS)

## Root cause (confirmed)
1. S06 DEFECT (real): primary GGUF loader matched `attn_q.bias` to the `attn_q.`
   weight pattern, misrouting the 84 Qwen2 QKV biases into the weight slots.
   -> `lw.bq/bk/bv` were EMPTY -> bias never applied -> wrong output (64787 ' madrid').
2. S07 MISTAKE (mine): I added a SECOND bias add in LinearW's CPU path, but LinearW
   ALREADY applies bias at its end ("Add bias" block, ~line 7076). This caused a
   DOUBLE bias (q[0]=0.738 = 0.451 + 0.287). Removed the duplicate.

## Fix (net)
- S06: route `attn_q.bias`->`lw.bq`, `attn_k.bias`->`lw.bk`, `attn_v.bias`->`lw.bv`,
  `attn_o.bias`->`lw.bo` BEFORE the `attn_q.`/`attn_k.`/`attn_v.` weight patterns
  (Deep2Engine.cpp ~line 3348). Also added mapTensor/bindOne bias bindings.
- S07: REMOVED the duplicate CPU-path bias add (kept the original single add).
