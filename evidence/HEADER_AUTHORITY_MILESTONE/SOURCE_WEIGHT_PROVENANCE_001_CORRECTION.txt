=============================================================================
EXPLANATION
=============================================================================

The original SOURCE_WEIGHT_PROVENANCE_001 concluded that GGUF corruption
occurred during conversion/quantization because NaNs were observed in the
GGUF read at the stale data-start offset (3972000).

Subsequent ROM_OFFSET_AUTHORITY_001 established that the authoritative
data-start offset is 3996416, not 3972000. The 24,416-byte stale offset
caused reads from the wrong file position, producing NaN values that were
incorrectly attributed to GGUF artifact corruption.

The original GGUF file is NOT corrupted. The NaNs were a read-alignment
artifact, not a quantization/conversion defect.

OFFICIAL_SOURCE_WEIGHT=FINITE (unchanged)
GGUF_WEIGHT=FINITE (when read at authoritative offset)
ROOT_CAUSE=STALE_DATA_START_OFFSET (corrected)
