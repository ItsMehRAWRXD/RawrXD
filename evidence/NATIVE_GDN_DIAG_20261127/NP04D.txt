RAWRXD NP-04D — separate initial uploads from re-uploads — 2026-11-27
Mode: DIRECT_EXECUTOR. Hardware: NOT used (held). Build: full MSBuild compile+link.

OBJECTIVE (NP-04D): distinguish a first-ever device upload of a compressed weight
from a re-upload after eviction. Previously both were counted only as
weight_cache_misses, so repeated-transfer cost was invisible.

INSPECTION (no duplication): existing residency accounting in
src/vulkan_compute.cpp EnsureQuantWeight already provides weight_cache_hits (:3052),
weight_cache_misses (:3146), evictions budget/trim (:3108/:3203), upload_bytes,
device_bytes_live/peak, pin/lease/retire/reap. NP-04D adds ONLY the missing
initial-vs-reupload attribution; it does not duplicate hits/misses/evictions.

CHANGE (4 files, additive, cold path only — miss branch of EnsureQuantWeight):
1. include/vulkan_compute.h — GpuCounters: + weight_initial_uploads, weight_reuploads
   (documented to sum to weight_cache_misses). VulkanCompute: + quant_seen_weights_
   (unordered_set<const void*>), cleared with the cache on Cleanup.
2. src/vulkan_compute.cpp — EnsureQuantWeight miss branch: after ++weight_cache_misses,
   insert(packed) into quant_seen_weights_; first insert => ++weight_initial_uploads,
   else ++weight_reuploads. Cleanup clears quant_seen_weights_ beside the cache.
3. src/deep2/quant_dot_dispatch.hpp — BackendStats + CacheStats: + weight_initial_uploads/
   weight_reuploads (BackendStats) and initial_uploads/reuploads (CacheStats).
4. src/deep2/quant_dot_dispatch.cpp — BackendCounters() and GetCacheStats()/
   GetCacheStatsOn() copy the two counters.

No control-flow change to the hot dispatch path; only the cache-miss branch (cold)
gains two set operations. No new dependencies, stubs, or backend substitution.

CORRECTNESS VERIFICATION (source-confirmed, NP-04D edge cases):
- Failed uploads NOT counted: AllocateBuffer failure returns at vulkan_compute.cpp:3127-3131
  and CopyHostToBuffer failure returns at :3137-3144, BOTH before the seen-insert and
  before ++weight_cache_misses (:3146). So a failed attempt is never classified as an
  initial upload or a successful miss.
- Concurrent misses serialized: the whole lookup/upload/evict path runs under
  std::lock_guard quant_mu_ (:3030), so first-upload attribution cannot race.
- Model unload/reload: Cleanup clears quant_seen_weights_ beside quant_weight_cache_
  (:3517-3518), so a reload starts fresh (first uploads counted initial again).
- Bounded growth: the set holds distinct weight keys for the model lifetime (bounded by
  tensor count) and is cleared on Cleanup; no unbounded cross-model growth.
- Reconciliation invariant: weight_initial_uploads and weight_reuploads each increment
  exactly once per SUCCESSFUL miss, immediately after ++weight_cache_misses, so
  initial_uploads + reuploads == weight_cache_misses (successful-miss population) by
  construction. weight_cache_misses excludes failed attempts (see above).
