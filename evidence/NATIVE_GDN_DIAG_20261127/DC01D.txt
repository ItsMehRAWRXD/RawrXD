ROOT CAUSE (source-confirmed, supersedes the fused/gated and GDN-branch hypotheses):
- There are TWO distinct VulkanCompute implementations:
    (a) CANONICAL  — include/vulkan_compute.h (class VulkanCompute), impl src/vulkan_compute.cpp.
        Used by the standard (non-GDN) path via QuantDot::Gpu() (a function-local static).
    (b) Deep2::VulkanCompute — src/deep2/vulkan_compute.h, impl src/deep2/vulkan_compute.cpp.
        Returned by GetDeep2VulkanCompute(); used only by the GDN path (DispatchGdn).
- The canonical GpuCounters already tracks submits/waits/submit_ms/wait_ms and increments them
  at EVERY real vkQueueSubmit/vkWaitForFences (src/vulkan_compute.cpp:276/287, 1568/1577,
  1787/1807, 2307/2331, 2706/2716, 2762/2767, 2804/2809, 2949/2955). Accessor GetGpuCounters()
  at include/vulkan_compute.h:262. QuantDot::BackendCounters() mirrors it (quant_dot_dispatch.cpp:530).
- The receipt read GetDeep2VulkanCompute().QueueSubmitCount() — the WRONG class/instance (b) —
  which the standard path never uses => 0. That is the persistent zero-counter anomaly.

FIX (3 source files, additive/corrective, no control-flow change):
1. src/deep2/runtime_graph_executor.hpp/.cpp — Executor accessors now read the CANONICAL device:
     SubmitCount()  = QuantDot::BackendCounters().submits   (canonical vkQueueSubmit, cumulative)
     WaitCount()    = QuantDot::BackendCounters().waits      (canonical fence waits)
     SubmitMsTotal()/WaitMsTotal() = canonical host submit/wait ms
     BatchSubmitCount() = gpu_batch_submissions_  (executor QuantDot batch completions — SEPARATE unit)
     GdnSubmitCount()   = GetDeep2VulkanCompute().QueueSubmitCount()  (SEPARATE Deep2 instance, GDN path)
   The earlier summed SubmitCount() (batch + singleton) was REVERTED: a batch completion is not one
   queue submission (one EndBatch chunks into N EndQuantDotBatch submits); different units, never summed.
2. tools/deep2_strata_chat.cpp — SubmissionSnapshots now captures a TelemetrySample
   {submits,waits,batch,gdn,submit_ms,wait_ms} at s0/s1/s2; s0 moved to BEFORE prefill (was after).
   Receipt emits per-request deltas, each key exactly once:
     queue_submits, gdn_queue_submits, batch_completions, waits, submit_ms, wait_ms,
     submits_scope, submits_valid, waits_valid, timing_valid, telemetry_valid.
   Validity is independent; telemetry_valid = submits_valid && waits_valid && timing_valid
   (the exact required contract). The duplicate hardcoded "telemetry_valid" key was removed.
   GDN activity is reported on its own gdn_queue_submits field (never omitted, never combined).
