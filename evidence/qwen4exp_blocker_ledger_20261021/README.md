# Qwen4Exp blocker ledger

The reverse-engineering contract says what each operator requires. It did not
say which parts of each requirement the engine can already execute, which have
a lowering artifact, and which of those artifacts have been run on a device.

This is that: a machine-generated ledger, produced from the real manifests and
the real artifacts, in which an operator is executable only when a lowering
artifact exists AND that artifact has been executed on a device and
reproduced a reference.

It is generated by `deep2_reverse_engineer`, which now writes the ledger as
part of the contract:

```
deep2_reverse_engineer --manifest SHARD1 --manifest SHARD2 \
    --shaders src/deep2/shaders --evidence evidence --out LEDGER.md
```

## The result

```
QWEN4EXP_REVERSE_ENGINEERED=1
TENSORS=1224 GEOMETRY=PASS
LEDGER=PASS EXECUTED_LOWERINGS=2/5
```

1,224 tensors, which is the canonical footprint: 1,080 persistent and 144
expert-streamed. The geometry checks pass against the canonical shapes.

## The ledger

| Operator | Artifact | Device execution | What is still missing |
|---|---|---|---|
| QSA | none | n/a | the indexer scoring and its top-k, and the compressed-key attention |
| GDN | none | n/a | the recurrent state update and the gated normalisation |
| PLE | `ple.comp` | **PASS** | the n-gram embedding and the key and value projections around it |
| HYPERCONNECTION | `hc_combine` | **PASS** | the mix path: the down projection, the per-stream silu, the up projection and the gated mean |
| SPARSE_MOE | none | n/a | the router and its top-k, the grouped expert dispatch, and the MXFP4 and IQ2 formats |

The ledger also records, per operator, which of the existing Vulkan
primitives already cover which parts of it. That is what decides the next
slice:

- **QSA**: the indexer projections and norms are covered by `OP_GEMV_F32` and
  `OP_RMSNORM`. The scoring and the top-k are not.
- **GDN**: the projections are covered. The state update is a scan, not a
  projection, and there is no primitive for it.
- **PLE**: the norms are covered. The depthwise short convolution was not, and
  is now lowered and executed.
- **HYPERCONNECTION**: the down and up projections are covered by
  `OP_GEMV_F32` and the combine addition by `OP_RESIDUAL`. The per-stream
  silu mean, the sigmoid-gated mean and the grouped RMSNorm are not.
- **SPARSE_MOE**: the activation is covered by `OP_SWIGLU`, and one expert's
  projection by the packed GEMV. The router top-k, the grouped dispatch and the
  expert formats are not.

## The rule the ledger enforces

An operator is executable only when a lowering artifact exists AND that
artifact has been executed on a device and reproduced a reference.

A compiled shader is not an executable operator. An operator that has never
run is not an executed one. The ledger fails closed when an artifact exists
without a passing execution receipt, and the receipt is only accepted when it
says `RESULT: PASS`: a run that reported BLOCKED, or that failed, is not an
execution.

This is the distinction that the two static checkpoints could not make. Both
reported "compile clean" and neither had run anything.

## What the ledger does not establish

Nothing here is bound into the runtime graph. The model is still fail-closed
and still `NOT_CERTIFIED`. This says which slice is next, and it says it from
evidence rather than from intent.
