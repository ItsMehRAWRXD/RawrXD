--- ROOT CAUSE OF CPU TPS (measured FORWARD=959ms, LOGITS=286ms per token) ---
The model is Q4_K_M, so nearly every LinearW hits gemv_q4_k_scalar (Q4_K) and
gemv_q6_k_scalar (Q6_K). Both are SCALAR. Additionally LinearW calls the GEMV
kernel SINGLE-THREADED (Deep2Engine.cpp:2349; thread pool not used for the matmul).

--- SAFE UNLOCKS (correctness-preserving) ---
1. THREAD the scalar GEMV over independent output rows in LinearW.
   Bit-identical (each output row is an independent dot product) -> preserves
   exact scalar correctness, ~Ncore speedup. LOW RISK.
2. Q4_K AVX2/AVX512 kernel: EXISTS, no defect note. HIGH VALUE but MUST pass an
   empirical parity gate vs scalar (sibling AVX2 kernels here are documented
   defective, so absence of a comment is not proof). Enable only if greedy
   output is identical to the scalar baseline.

--- BLOCKED UNLOCKS (do NOT enable without fixing the kernel first) ---
Q5_K, Q6_K, Q3_K, Q4_0, Q4_1 optimized kernels are documented defective/unverified.
